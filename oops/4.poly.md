# Polymorphism in Java — Practical Understanding First

Before learning:

* Compile-time polymorphism
* Runtime polymorphism

you must deeply understand **what polymorphism actually solves in real software**.

---

# What is Polymorphism?

Polymorphism means:

> **One thing behaving in multiple forms**

In Java:

* One method name
* One interface
* One reference

can represent different behaviors.

---

# Real-Life Meaning

Think about this:

## Example: “Payment”

Different payment methods:

* UPI
* Credit Card
* Net Banking
* PayPal

All do:

```text
pay()
```

But internally:

* UPI works differently
* Credit card works differently
* Net banking works differently

Same action:

```text
pay()
```

Different implementations.

This is polymorphism.

---

# Why Polymorphism Exists

Without polymorphism:

```java id="i4v6p5"
if(type.equals("UPI")) {
    // UPI code
}
else if(type.equals("CARD")) {
    // Card code
}
else if(type.equals("NETBANKING")) {
    // Net banking code
}
```

Problems:

* Huge if-else chains
* Hard to maintain
* Hard to extend
* Tight coupling

---

# With Polymorphism

```java id="x6n3oc"
Payment p;

p = new UPI();
p.pay();

p = new CreditCard();
p.pay();
```

Now:

* No if-else
* Easy extension
* Cleaner architecture
* Flexible systems

This is why enterprise applications heavily use polymorphism.

---

# Core Idea

## SAME MESSAGE → DIFFERENT RESPONSE

```text
pay()
```

Different objects respond differently.

---

# The 3 Pillars Behind Runtime Polymorphism

Runtime polymorphism works because of:

1. Inheritance
2. Method overriding
3. Upcasting

Without these, runtime polymorphism cannot happen.

---

# Step-by-Step Practical Example

---

# Step 1: Parent Class

```java id="z6v7z0"
class Animal {

    void sound() {
        System.out.println("Animal makes sound");
    }
}
```

This is generic behavior.

---

# Step 2: Child Classes

```java id="hbrl2u"
class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
```

```java id="2h0zdl"
class Cat extends Animal {

    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}
```

Each child changes behavior.

---

# Step 3: Polymorphic Reference

```java id="i85m5y"
Animal a;
```

This reference can point to:

* Dog
* Cat
* Any Animal subclass

---

# Step 4: Runtime Object Assignment

```java id="a1ujq8"
a = new Dog();
a.sound();
```

Output:

```text
Dog barks
```

Now:

```java id="sm2xj5"
a = new Cat();
a.sound();
```

Output:

```text
Cat meows
```

---

# Important Observation

Same reference:

```java
Animal a
```

Same method:

```java
sound()
```

Different outputs.

That is polymorphism.

---

# What Actually Happens Internally

This line:

```java id="ehoj3f"
Animal a = new Dog();
```

contains TWO things:

| Part   | Meaning        |
| ------ | -------------- |
| Animal | Reference type |
| Dog()  | Actual object  |

---

# JVM Decision Process

When:

```java id="pr5w9m"
a.sound();
```

runs, JVM checks:

## Step 1

Does reference type have `sound()`?

* YES → compile successful

## Step 2

At runtime JVM checks:

```text
Actual object = Dog
```

## Step 3

Dog's overridden method executes.

You don't want:

```text

```

You want:

# Two Types of Polymorphism in Java

| Type                      | Meaning                            |
| ------------------------- | ---------------------------------- |
| Compile-Time Polymorphism | Method selected during compilation |
| Runtime Polymorphism      | Method selected during execution   |

Now let's deeply study both.

---

# 1. Compile-Time Polymorphism

Also called:

* Static polymorphism
* Early binding
* Method overloading

---

# What is Compile-Time Polymorphism?

Method Overloading means:

Same method name with:

* Different parameters

Compiler decides method before program runs.

---

# Example

```java id="wl7l8w"
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}
```

---

# Method Calls

```java id="qvc7u4"
Calculator c = new Calculator();

c.add(10, 20);
c.add(10.5, 20.5);
c.add(1, 2, 3);
```

Compiler immediately knows:

* which method to call

before execution.

---

# Why Called Compile-Time?

Because JVM does NOT decide.

Compiler decides using:

* method name
* parameter count
* parameter type
* parameter order

---

# Internal Resolution

Compiler creates method signatures.

Example:

```text
add(int,int)
add(double,double)
add(int,int,int)
```

Each signature is unique.

---

# Important Rule

Return type alone cannot overload.

❌ Invalid:

```java id="uwi2bw"
int test()
double test()
```

Because signatures are same.

---

# Real Use Cases of Overloading

---

# Example: println()

```java id="8wd6nw"
System.out.println(10);
System.out.println("Hello");
System.out.println(5.5);
```

Same method:

```text
println()
```

Different parameter types.

This is overloading.

---

# Advantages of Overloading

* Improves readability
* Same logical operation
* Cleaner APIs
* Convenience methods

---

# Types of Overloading

## 1. Change Number of Parameters

```java id="z9jy7i"
show(int a)
show(int a, int b)
```

---

## 2. Change Data Type

```java id="l3l2dg"
show(int a)
show(double a)
```

---

## 3. Change Order

```java id="4x1vh7"
show(int a, String b)
show(String b, int a)
```

---

# Compile-Time Binding

\text{Method Selection Happens During Compilation}

Compiler already fixes method address.

No runtime decision needed.

Therefore:

* Faster
* Efficient

---

# 2. Runtime Polymorphism

Also called:

* Dynamic polymorphism
* Late binding
* Method overriding

---

# What is Runtime Polymorphism?

Method Overriding means:

Child class changes behavior of parent method.

JVM decides method at runtime.

---

# Example

```java id="yq2u7r"
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}
```

---

## Child Class

```java id="zn1a3n"
class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
```

---

# Runtime Dispatch

```java id="4c3uwg"
Animal a = new Dog();

a.sound();
```

Output:

```text
Dog barks
```

---

# Why Runtime?

Compiler only knows:

```text
Reference type = Animal
```

Actual object decided later:

```text
Dog object
```

So JVM decides method during execution.

---

# Dynamic Method Dispatch

Java uses:

* Virtual method tables (vtable)
* Dynamic lookup

At runtime:

1. JVM checks actual object
2. Finds overridden method
3. Executes child version

---

# Memory-Level Understanding

```java id="gf8bxq"
Animal a = new Dog();
```

Stack:

```text
a → reference
```

Heap:

```text
Dog object
```

Method call:

```java
a.sound()
```

JVM checks:

```text
Object type = Dog
```

Executes:

```text
Dog.sound()
```

---

# Why Runtime Polymorphism Is Powerful

Allows:

* Extensible systems
* Plugin architectures
* Framework design
* Loose coupling

# Compile Time vs Runtime Polymorphism

| Feature            | Compile Time | Runtime         |
| ------------------ | ------------ | --------------- |
| Also Called        | Overloading  | Overriding      |
| Decision Time      | Compile time | Runtime         |
| Binding            | Early        | Late            |
| Inheritance Needed | No           | Yes             |
| Speed              | Faster       | Slightly slower |
| Flexibility        | Less         | More            |
| Method Signature   | Different    | Same            |
| Object Needed      | No           | Yes             |
